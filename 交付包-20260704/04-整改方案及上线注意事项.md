# 整改方案及上线注意事项

## 已发现并整改的问题

### 1. 手机端管理端发布活动保存失败

原因：

- 未开通报名审核权限的商家可能提交 `requireReview=true`。
- API 会拒绝该请求，导致保存或发布失败。

整改：

- 手机端根据当前商家权限禁用报名审核。
- 保存 payload 时自动把未开通权限商家的 `requireReview` 转为 `false`。
- 接口增加兜底校验，所有入口都不能绕过商家权限。

### 2. 已上线活动保存时状态流不稳

原因：

- 手机端“保存”可能把已上线活动按草稿保存。
- 需要平台审核的商家编辑已上线活动时，前端可能误提示不能发布。

整改：

- 已上线活动保存时保持 `open`。
- 待审活动保存时保持 `pending_approval`。
- 直接发布按钮只在适合的状态显示。
- 加入重复点击保护。

### 3. PC 管理后台同类报名审核权限问题

原因：

- 平台超管编辑活动时，PC 后台默认允许报名审核，没有按活动所属商家判断。

整改：

- PC 后台按活动所属商家的 settings 判断 `registrationReviewEnabled`。
- 未开通商家不能保存报名审核。

### 4. 报名审核权限被误判成活动审核权限

原因：

- API 权限映射里泛化 `/approve` 规则过宽。
- `registrations/:id/approve` 被误判为 `activity.approve`。

整改：

- 活动审核权限只匹配 `activities/.../approve|reject`。
- 报名审核正确匹配 `registration.manage`。
- 新增单测防止回归。

### 5. 数据库迁移缺失风险

原因：

- 本地验收环境缺少 `launchConfig` 等新迁移字段。
- 最新代码访问这些字段时会报错。

整改：

- 本地已执行迁移，101 个迁移全部完成。
- 部署文档强制加入 `npm --prefix apps/api run migration:run`。

## 仍需上线注意

1. 本次改动包含小程序端代码，必须重新上传小程序并提交审核。
2. 服务端部署必须先备份数据库，再执行迁移。
3. 小程序审核通过前，线上正式版仍不会包含本次手机端管理端修复。
4. 部署后建议先用体验版复测：
   - 手机管理端发布活动。
   - 需审核商家提交审核。
   - 平台超管通过审核。
   - 用户报名、审核、签到。
5. 如果线上已有自定义账号密码，不要用交付默认密码覆盖。
6. 测试数据可保留，也可后续在后台按标题关键词“交付验收”筛选下架。

## 是否还有优化建议

建议后续排期：

1. 在手机端管理端增加更明确的商家套餐权限说明。
2. 在活动发布页显示“当前活动将直接发布/提交平台审核”的状态提示。
3. 将浏览器验收脚本拆成轻量版和全量版，轻量版只跑活动发布/报名/签到主链路。
4. 给数据库迁移状态做后台可视化提醒，避免代码已更新但数据库未迁移。
