## 本次修复点

1. 手机端管理端活动编辑页按商家权限处理“报名审核”：
   - 未开通报名审核权限的商家，前端禁止打开 `requireReview`。
   - 保存请求会自动把 `requireReview` 置为 `false`，避免接口拒绝。
2. 手机端管理端活动状态保存修复：
   - 已上线活动保存时保持 `open`，不会误降为草稿。
   - 待审活动保存时保持 `pending_approval`。
   - 需要平台审核的商家不能直接发布 `open`，只能提交审核。
3. PC 管理后台活动表单修复：
   - 平台超管编辑活动时，也按活动所属商家的套餐权限判断能否开启报名审核。
4. API 兜底修复：
   - 无论商家账号还是平台超管，只要活动所属商家未开通报名审核，都不能保存 `requireReview=true`。
5. 权限映射修复：
   - `registrations/:id/approve|reject` 现在正确映射到 `registration.manage`。
   - 避免被泛化 `/approve` 规则误判成 `activity.approve`。
6. 数据库迁移检查：
   - 本地发现缺少 `launchConfig` 等新字段，已执行迁移。
   - 部署命令中必须包含 `npm --prefix apps/api run migration:run`。
