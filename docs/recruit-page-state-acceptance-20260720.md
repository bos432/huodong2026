# 大使与院长招募页面状态一致性验收报告

## 1. 范围

- 日期：2026-07-20
- H5：`http://127.0.0.1:18080/h5/`
- 商家：`qiwai-showcase`
- 页面：文化大使招募、院长招募。
- 检查：商家请求代次、套餐功能门、加载/错误/重试、提交互斥、持久提交错误、移动布局和 API 故障恢复。

## 2. 发现的问题

状态一致性合同原覆盖 71 个移动页面中的 53 个，剩余 18 个页面未被纳入合同。本批确认两个招募页面存在真实缺口：

- 文化大使招募未使用租户请求代次守卫，商家切换时旧响应可能覆盖新页面。
- 两页加载失败均只显示短暂 toast 或静默使用默认内容，无法区分真实配置与请求故障。
- 院长招募未执行套餐功能门复核。
- 两页提交失败缺少页面内持久错误；院长招募没有函数入口级重复提交保护。

## 3. 整改

- 文化大使招募接入 `createTenantLoadGuard`，仅当前商家、当前请求代次可以写入配置和案例。
- 两页在 `onShow` 时刷新功能开关，使用 `guardCurrentPageFeature` 阻止未授权页面继续加载。
- 增加加载中、`role=alert` 错误态和“重新加载”动作；错误时不再展示可能过期的默认配置。
- 提交函数入口统一拦截 `submitting/submitted`，请求开始前加锁。
- 提交错误使用安全文本写入页面并通过 `aria-live=assertive` 播报；成功后锁定表单。
- 保留稳定业务幂等键，失败重试不会生成新的申请业务键。
- 状态一致性合同新增两个页面，未覆盖页面由 18 个降至 16 个。
