# UI 与架构后续优化清单

## P0：上线前必须完成

- 本轮已完成：移动端活动首页在装修缺少活动模块时使用真实活动兜底，隐藏空历史心得模块，避免首页只剩导航或出现重复空态。
- 本轮已完成：配置体检对旧密钥/失效密文安全降级，不再因单条历史加密配置导致接口 500；缺失配置会进入 warning/上线前确认列表。
- 本轮已完成：独立 Worker 心跳、ready、metrics 和 API external 模式已在本地启动并验收。
- 本轮已完成：普通用户报名、线下收款确认、报名成功、签到码、活动空间，以及运营/财务/平台/签到角色浏览器验收通过。
- 本轮已完成：自动短信在关闭总开关、关闭场景或会员失效时保留幂等的“已抑制”记录；不创建任务、不调用服务商，便于通知中心追踪原因。
- API 与 Worker 分进程部署，并将 `/api/health/worker` 纳入监控；任务死信、积压和 Worker 心跳失效必须告警。
- 后台真实配置短信服务商、模板、余额告警、支付回调和退款服务商；完成一次可追踪的报名成功通知测试。
- 375/390/760 视口检查首页、活动列表、详情、报名、支付确认、活动空间、我的和订单；微信工具与真机单独验收。
- 复核租户切换、默认商家、隐藏切换按钮、装修顺序和底部导航配置，确保后台预览与用户端实际顺序一致。
- 保持真实报名人数、剩余名额、评价和成员数据；没有数据时使用空态，不补头像或社交证明。

## P1：运营效率

- 短信通知中心增加按活动、会员 ID、手机号后四位、请求 ID 和任务状态筛选；支持重试前展示失败原因和幂等键。
- 活动编辑器增加发布检查清单：封面、时间地点、票种、报名字段、退款规则、活动空间和通知模板均有明确状态。
- 首页装修增加草稿、预览、发布、回滚版本，以及“已结束活动默认隐藏”的可见性设置。
- 活动空间增加公告定时发布、群二维码有效性检查、问答审核队列和客服上下文。
- 可选补充验收：在内容运营专项测试中补做一条活动空间测试提问，验证运营审核/回复和用户端回显；正式运营前不使用真实用户内容做测试。
- 订单页继续保持状态分组稳定，失败时显示重试和请求编号，不用无限加载遮盖接口错误。

## P2：增长与产品化

- 用活动报名、到场、评价、复购和邀请转化构建真实运营漏斗。
- 在获得用户授权和审核能力后，再评估活动圈子、群聊、同伴展示和位置共享；先补举报、黑名单、内容审核和数据合规。
- 微信订阅消息与短信做成本分层：高价值交易状态优先，普通提醒优先订阅消息，失败才进入短信兜底。
- 增加租户级运营健康分、通知送达率、支付回调成功率、退款时效和活动复购率看板。

## 当前风险

- 本地浏览器已证明真实本地 API、数据库和沙箱报名/收款链路；仍不能替代线上真实短信、真实支付服务商和微信真机验收。
- 本地配置体检当前是 development warning，正式上线前必须按生产环境报告处理密钥、域名、短信、支付和 Worker 配置。
- 微信原生客服坐席是小程序平台级配置，不能承诺在同一个小程序内按租户动态切换坐席。
- H5 与小程序构建通过不等于微信审核通过；扫码相机、长按识别和订阅消息必须真机验证。
- 真实支付、真实短信和生产数据库 migration 都需要发布负责人在服务器上确认配置和备份结果。
