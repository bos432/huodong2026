- 商户结算同店并发生成、财务调整、复核、付款/扣回、逐笔一致性和状态事件已通过真实 MySQL/API/PC 验收。

## 专项验收

```powershell
npm run acceptance:mall-settlement-ledger
```

- 脚本自动登录并选择最近存在已通过退款的活跃店铺。
- 两路同店、同业务键并发生成只返回结算单 27。
- 两路并发财务调整只增加 1.23 元且只生成一个 adjusted 事件。
- 两路并发复核只生成一个 approved 事件。
- 未填写流水号或凭证时付款接口返回 400。
- 两路并发付款/扣回只生成一个 paid 事件并返回同一结算单。
- 数据库核对逐笔流水总数等于不同 `operationKey` 数量。

## 整改记录

1. 修复同店并发生成时一路成功、一路暴露唯一键 409 的问题。
2. 结算生成先锁定店铺，再以当前读检查业务键，覆盖第二事务等待首事务提交后的重放时序。
3. 保留唯一键异常后的业务键回读作为末端并发恢复，且校验租户和店铺归属。
4. 修复结算详情、逐笔明细和事件 eager relation 触发 MySQL 61 表 join 上限。
5. 结算主单只加载租户/店铺，明细只加载订单/退款/佣金，事件和一致性计算关闭 eager。
6. 验收脚本从依赖手工令牌和业务 ID 升级为自动登录、自动发现店铺和完整并发重放测试。
