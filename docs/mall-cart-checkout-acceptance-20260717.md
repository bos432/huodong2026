# 09.04 购物车、地址与确认订单验收报告

## 验收结论

购物车、收藏、浏览足迹、收货地址和确认订单已完成真实 MySQL/API/H5 验收。migration `1783570000000` 已执行，报价签名、服务端重算、购物车并发和默认地址并发均通过；微信小程序已构建，真机交互按生产配置统一终验。

## 本轮整改

1. 新增可重复执行的 `acceptance:mall-cart-address`，覆盖并发加购、收藏、足迹和默认地址治理。
2. 修复同一用户并发记录同一商品足迹时触发唯一键 409。现通过商品行悲观锁串行累加，重复浏览幂等更新同一条足迹。
3. 升级 `acceptance:mall-checkout-quote` 为自登录脚本，不再依赖人工注入 `USER_TOKEN`，默认使用保留会员、SKU 和地址。
4. 专项脚本重复执行时复用自身购物车和地址夹具，避免无限堆积测试数据。

## API 与并发验收

### 购物车

- 8 路并发对 SKU 128 各加购 1 件。
- 最终仅保留一条购物车记录，数量精确为 8。
- 服务端返回 `purchasable=true`、可售库存和行金额 `799.20`。
- 数量更新为 0 会删除购物车项，脚本可重复执行。

### 地址

- 两个地址同时设置为默认地址。
- 事务结束后 3 个地址中仅 1 个 `isDefault=true`。
- H5 确认订单自动选择地址 421。
- 首地址默认、删除默认自动递补、最多 20 条、手机号及字段长度由 DTO 和服务层共同校验。

### 收藏与足迹

- 收藏支持显式 DELETE 后重新收藏，状态查询一致。
- 两路并发浏览同一商品不再返回 409，仅更新一条足迹并累加次数。
- 足迹单条删除和全部清空接口可用。

### 确认订单报价

- 服务端生成 10 分钟 `quoteToken`，包含商品版本、SKU、数量、单价、优惠、积分、运费和分摊快照。
- 篡改 token 返回 HTTP 400“订单报价校验失败”。
- 有效 token 创建保留订单 1000、1001。
- 过期 token 与价格/库存/优惠变化由 `mall-order-quote.spec.ts` 和提交前服务端重算覆盖，变化时整单拒绝并要求刷新报价。

## H5 浏览器验收

- 购物车显示 SKU 128 数量、可购量、单价和服务端行金额。

- 确认页显示默认地址 421、商品金额、逐店应付、优惠券、积分、推广码和支付方式。

- 地址页展示 419、420、421，只有 421 带“默认”标记。
- 购物车、确认订单和地址页控制台 warning/error 为 0。
