## 2. 实现结果

新增接口：

- `GET /api/admin/unified-orders/:businessType/:id`
- `GET /api/admin/unified-orders/export`

实现规则：

- 活动、课程、商城分别要求 `order.view`、`course_order.view`、`mall.order.view`。
- 导出独立要求 `order.export`，不随查看权限自动授予。
- 活动订单按关联活动 ID 执行岗位 `activity_ids` 数据范围。
- 商城订单按管理员店铺授权范围过滤。
- 详情统一返回订单、金额构成、时间线、支付、退款和商品明细；Excel 最多导出 10000 条。
- 列表和详情使用白名单投影，手机号服务端脱敏；业务快照递归移除密码、微信身份、渠道原始报文、地址、收件人和联系方式。
- PC 增加统一订单菜单、导出入口、逐行详情抽屉、加载失败重试和移动端布局。
- 金额构成统一显示“原价、商品金额、运费、优惠金额、会员优惠、积分抵扣、使用积分”，不暴露内部英文键。

## 3. 浏览器发现与整改

### 3.1 活动订单岗位范围 SQL

最小权限账号首次进入默认订单页时返回 500，数据库错误为：

`Unknown column 'order.orderId' in 'IN/ALL/ANY subquery'`

根因是公共活动数据范围函数把主订单 `order` 与退款、支付流水使用了同一关联字段。现已拆分：

- 主订单使用 `order.id IN (...)`。
- 退款、支付、账单和回调使用各自的 `alias.orderId IN (...)`。

专项单测固定精确 SQL 条件。修复后默认订单页返回指定活动 200 张订单，跨活动详情仍为 404。

### 3.2 菜单可达性

统一订单路由原先可通过深链访问，但平台和租户财务菜单均缺少入口。现已在两类“票务与财务”菜单增加“统一订单中心”，并纳入平台切换商家时的路由范围同步。

### 3.3 移动详情

390x844 下抽屉稳定宽度为 `374.39px`，左右边界为 `15.61px / 390px`；页面和文档滚动宽度均不超过视口。抽屉刚切换视口时存在正常过渡动画，稳定后无裁切或横向溢出。
