## 技术栈与插件依赖

项目确实依赖第三方框架、组件库和 SDK，但没有依赖不可控的闭源业务插件。

### 后端

- NestJS 11：API 框架。
- TypeORM + mysql2：数据库访问与迁移。
- Passport/JWT + bcryptjs：认证与密码校验。
- class-validator/class-transformer：请求参数校验。
- AWS S3 SDK：OSS、COS、S3 兼容对象存储适配。
- 腾讯云 SDK、Nodemailer：短信与邮件渠道。
- ExcelJS、QRCode：导出、二维码和凭证生成。
- Vitest：自动化测试。

### 管理后台

- Vue 3、Vue Router、Vite。
- Element Plus 与图标库。
- Axios：API 请求。
- html5-qrcode、qrcode：扫码核销与二维码。

### H5 与微信小程序

- uni-app Vue 3 编译链。
- `@dcloudio/uni-h5`、`@dcloudio/uni-mp-weixin`。
- 微信开发者工具 CLI；API 包还包含 `miniprogram-ci`。

### 部署与运维

- Node.js 22、npm 11.6.2、PM2、Nginx、MySQL 8.4。
- Docker Compose 为可选的本地/标准化部署方式。
- GitHub Actions 负责依赖审计、密钥扫描、测试、门禁和四端构建。

## 数据库检查

- 当前源码登记 203 个实体表，迁移合同测试全部通过。

## 仍需处理

### P1：下一次部署必须处理

1. 部署本次 API 修复并重启 PM2，观察业务任务积压从 168 降到 0。默认每 30 秒处理最多 20 条，预计约 5 分钟清空。
2. 配置 OSS、COS 或 S3 兼容对象存储。当前本地文件存储可运行，但单机故障、扩容和静态资源迁移风险较高。
3. 为 `monitor:health` 配置定时执行和告警 Webhook。当前监控能发现积压，但没有 Webhook，告警不会主动发送。

### P2：按业务启用

1. 开启自动关单任务，否则待付款订单需要人工处理。
2. 开启通知调度任务，否则预约通知不会自动发送。
3. 配置短信、邮件和微信订阅消息渠道；未使用的渠道可继续关闭。
4. 管理后台 Element Plus 主资源约 775 KB（gzip 约 246 KB），后续可通过按需组件引入进一步降低首屏资源。
5. 在各子项目补充 Node `engines` 约束，统一声明 Node 22，避免本机 Node 25 直接执行 uni-app 构建。
6. 开发/发布工具链的完整 `npm audit` 仍有历史告警，主要来自 `miniprogram-ci` 的旧 Babel 依赖和 Vitest 2。这些包不会进入 `npm ci --omit=dev` 的 API 生产镜像，但源码直部署时应避免让小程序发布工具与线上 API 共用高权限进程；中期建议拆为独立发布工具或容器。

### P3：单独兼容升级，不在当前生产修复中混入

- Vue Router 5、Vite 8、TypeScript 7、Vitest 4、TypeORM 1.x。
- uni-app 新编译器版本。
- bcryptjs 3、uuid 14 等大版本。

这些升级可能改变路由、构建、类型检查、数据库行为或小程序产物，应建立独立分支并重新完成 H5、小程序真机和数据库迁移验收。
