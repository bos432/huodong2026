# 订单跨租户加载整改报告（2026-07-29）

## 结论

“我的订单 - 全部”在租户 `qiwai-showcase` 下显示空列表或持续加载的根因已定位并修复。问题同时位于后端的租户筛选和前端的页面切换刷新策略，不是订单数据被删除或前端刻意隐藏。

截至本报告生成时，发布候选为 Git 提交 `724357976fcb3d78d8765cee989be432c9245818`。线上 `https://rd.chaimen666.com` 仍返回旧提交 `f8840c47`，因此线上和已上传的小程序体验版尚未包含本次修复，不能据旧包的现象否定修复结果。

## 问题链路

1. 会员切换到机构上下文后，旧 API 仅筛选 `registration.tenantId = 当前租户` 或 `activity.tenantId = 当前租户`。
2. 平台级活动与报名的 `tenantId` 均为 `NULL`，虽属于当前登录会员，却被上述条件排除。
3. 旧订单页面在 `onShow` 重复请求；页面切换或请求竞态时，成功数据可能被随后请求的空结果覆盖。
4. 订单总览使用 `Promise.all`；任一来源异常会让完整订单页失败，无法展示其他正常订单。

## 已完成整改

- API：当前租户上下文返回“当前租户订单 + 平台级订单”，不返回其他租户订单。
- API：平台级订单的详情、支付、取消和退款访问与列表规则保持一致。
- API：订单总览改为 `Promise.allSettled`；单个来源异常会标记来源并保留其他订单，不再让整页失效。
- H5/小程序：订单页按“租户代码 + 用户 ID + 会话令牌”缓存一分钟快照；页面返回时优先保留有效数据，用户可主动刷新。
- H5/小程序：加载失败显示明确错误和重试入口，不以空状态代替错误。
- 回归约束：新增平台订单隔离、订单总览降级及客户端状态一致性覆盖。
