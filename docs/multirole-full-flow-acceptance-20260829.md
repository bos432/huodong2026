## 2. 实际全流程结果

   - 手机：`13900000002`
   - 备注：`2026-08-29 多角色上线验收保留数据`
3. 报名和订单创建成功：
   - 报名 ID：`1`
   - 订单号：`OD17879855156201`
   - 金额：`¥99.00`
4. 用户端正确进入待付款报名详情。

结果：**通过。** 表单、确认弹层、订单详情和付款截止信息均可用。

### 2.2 后台确认线下收款

1. 管理员在订单管理确认“线下已收款”。
2. 页面提示失败：`积分规则不存在`。
3. 刷新后发现订单实际已变为“已付款”，报名实际已变为“报名成功”。
4. 生成支付流水：`TX17879856124141`。

结果：**核心数据已成功，但接口错误返回，判定失败。** 这是高风险的“写入成功但前端认为失败”。

### 2.3 活动空间与签到

1. 用户成功进入活动空间，可见公告空态、脱敏成员、问答、地点、邀请和客服。
2. 用户签到码可生成并展示。
3. 核销员从待核销名单填入签到码并执行核销。
4. 页面再次提示 `积分规则不存在`，刷新后实际已核销。
5. 核销员填写原因后成功撤销核销，以继续验证退款链路。

结果：**活动空间通过；核销主数据成功但接口错误返回，判定失败。**

### 2.4 活动问答和活动心得

1. 活动空间“提问”弹层可打开和填写。
2. 点击发布后页面意外回到“我的”，数据库未新增 `activity_space_posts`。
3. 活动心得页正确要求至少上传 1 张活动照片。
4. H5 打开文件选择后取消，按钮持续显示“上传中...”，提交按钮持续禁用，必须刷新页面恢复。

结果：**未通过。** 问答提交未落库；文件选择取消后的状态恢复异常。

### 2.5 退款申请与财务审核

1. 已签到状态仍显示“申请退款并保留公益金”，点击后服务端拒绝“已签到报名不能在线申请退款”。
2. 撤销核销后，用户成功申请退款 `¥94.05`，保留公益金 `¥4.95`。
3. 退款号：`URF17879861251511`。
4. 财务审核通过，退款状态“已完成”。
5. 订单变为 `partially_refunded`，但报名仍为 `approved`。
6. 用户仍可进入活动空间、获取签到码，并再次看到退款按钮，页面计算“预计可退 ¥4.95”。
7. 再次从干净路由进入报名详情时，页面又显示“报名记录不存在”，但数据库报名仍为 `approved`。

结果：**财务审核通过，但退款后的数据库状态、首次刷新状态和重新进入状态互相矛盾，判定失败。**

## 5. 缺陷清单

### P0 上线阻断

1. **收款和核销写入成功后返回失败。**
   - 复现：确认收款或核销后提示“积分规则不存在”，刷新后实际成功。
   - 风险：重复收款、重复核销、客服误判、操作员不敢继续。
2. **公益保留退款未终止报名资格。**
   - 复现：退款 `¥94.05` 后数据库报名仍为成功；首次刷新可继续看签到码和再次退款，重新进入又显示“报名记录不存在”。
   - 风险：退款用户可能继续占名额、参加活动或重复退款，同时历史报名详情不可追溯。
3. **H5 页面切换出现运行时错误。**
   - 错误：`Cannot destructure property 'firstElementChild' of 'rootRef.value' as it is null`。
   - 风险：页面切换白屏、动画/页面容器状态不稳定。

### P1 高优先级

1. 已签到页面仍展示退款按钮，前端可执行状态与后端规则不一致。
2. 活动空间问答发布后异常返回“我的”，且数据未落库。
3. H5 文件选择取消后永久停留“上传中...”。
4. 同一时间在 H5 与后台出现 8 小时时差；演示活动种子时间也被 UTC 转换污染。
5. 撤销核销后，经营看板仍按历史核销数显示签到率 `100%`，需要明确“当前有效核销”还是“历史核销事件”。

### P2 体验与维护

1. 财务/订单筛选存在 Element Plus `ElOption value=undefined` 警告。
2. 部分后台页面仍使用已弃用的 `el-checkbox label` 作为 value。
3. 核销员活动页“更多”菜单展示与只读身份无关的入口。
4. 系统设置对商家账号显示“平台默认配置”，作用域文案容易误导。
5. 管理后台主包存在超过 `500 kB` 的构建警告，需要继续拆包。
