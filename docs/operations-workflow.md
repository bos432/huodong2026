## 台账使用

财务或超管进入活动列表，选择「更多 → 经营台账」。读取需 `finance.view`，保存需 `finance.manage`，同时校验活动租户及活动数据范围。

自营模式自动计入已支付/已部分退款/已退款订单的原票款，扣除已完成退款；其他收入填写赞助、服务收入，勿重复录入票款。合作模式不计入商家票款，手工填写平台实际服务收入。实际成本填写场地、人员、物料、推广、通道费和结算支出等。

这里是经营估算，不是会计账簿或真实资金划转。未登记的成本、税费和待处理退款不会凭空计入。收入退回需调减原条目并写明备注。每次保存追加版本，冲突时须重新加载后合并，不能强行覆盖。

## 首批活动

### 渠道与周报

台账成本可选择具体活动渠道，留空表示非渠道成本，选择“未归因/自然访问”表示专门计入未归因流量的成本。跨活动渠道不可绑定。有效付费用户按当前仍有净支付且报名未取消/拒绝去重，首次付费按同商家的首次有效付款识别。缺失付款时间、没有分母或仅能查看部分活动时，相应获客成本不猜测。

测试活动创建时标记且不可回改；测试账号以服务器保存的 `sourceChannel=test` 明示。渠道分析、后续报名、经营周报区分测试口径；经营台账全票款与正式经营指标不是相同口径，不用于替代财务对账。生产环境测试活动不接受正式报名/报价。

商家工作台增加开通检查和北京时间自然周周报。检查项“已有配置”只说明字段存在，不代表认证、支付成功或通知到达。财务金额受财务查看权限控制，活动范围受限账号只看到自己可见活动；后续报名数不代表运营跟进导致成交。

本地商家「慢π本地策划验收」已有草稿 ID 3-10：周末共读、阅读行动局、街巷慢行、手机摄影漫步、茶席体验、手写时光、纸艺书签、主理人圆桌。内容在 `apps/admin/src/data/activity-starter-pack.json`，后台模板与导入器共用一份内容。

草稿中的零元、未来日期均是占位，不表示免费或确定举办。活动不会在公开列表展示，也没有虚假报名。运营定稿需确认：所属商家、实际日期、场地与负责人、人数、成本价格、费用包含、成团截止、取消退款、安全预案、客服、封面版权。完成后移除标题/正文/须知中的草稿标记，再执行发布检查和审核。

不要通过恢复历史版本或修改状态绕过未确认事项。模板本身不声称已签约嘉宾、真实场地、成效或销量。

## 导入与部署

先部署 API 与后台，并按既有备份流程审核迁移清单。新增迁移为 `1788566400000-ActivityOperationVersions.ts`，旧 API 回滚时可保留该新增表，不应为回滚代码而删除台账历史。服务器存在其他未执行迁移时，应单独审查，不能照搬本地空库初始化流程。

导入需在执行进程的环境变量设置 `API_BASE`、`TENANT_CODE`、`ADMIN_TOKEN`（有活动管理及财务管理权限），不要把令牌写进命令文档或日志。

```sh
node scripts/seed-activity-starter-pack.mjs
node scripts/seed-activity-starter-pack.mjs --apply
```

第一条只预览；远程写入必须额外指定 `--allow-remote`。导入仅创建草稿，不自动发布。重复运行跳过已存在/已编辑活动；未完成台账初始化的同名原始草稿可恢复初始化。不要并发运行导入器。

小程序端有代码变化，仍需重新上传体验版和真机验收。社交功能没有因此取得相应类目资格，不能借运行时隐藏来审核后开放。
