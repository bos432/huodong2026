# 公益贡献凭证验收报告（2026-07-21）

## 1. 业务口径

- 当前公益金由平台从活动订单收入中按配置比例计提，用户没有额外支付捐款。
- 本功能统一命名为“公益贡献凭证”，不得称为“捐赠证书”或公益捐赠票据。
- 凭证固定声明：`平台从订单收入中按规则计提，非用户额外捐款或公益捐赠票据`。
- 只有未来接入真实捐赠支付、退款、票据及合规流程后，才可另行建设“公益捐赠证书”。

## 2. 已交付功能

- 公益计提流水生成稳定唯一编号，格式为 `MPCGYYYYMMDD-流水ID-8位签名`。
- 仅 `certificateEligible=true`、`credit`、`charity_accrual`、金额大于 0 的流水可发放凭证。
- 本人下载使用完整持有人名称；公开图片与公开验真使用脱敏名称。
- 根据同订单公益计提与退款冲回净额，凭证自动显示“有效”“已调整”或“已冲正”。
- 后台公益流水新增“贡献凭证”列，提供预览与验真。
- H5 公益明细提供查看、下载、验真；统一验真页支持证书、服务证明、公益贡献三种模式。
- SVG 保持 1200x840 标准画布，同时按浏览器宽度自适应展示。

## 3. 运行时缺陷整改

真实接口首次验收发现凭证查询使用 `loadEagerRelations`，当前实体关系会触发 MySQL `Too many tables; MySQL can only use 61 tables in a join`。已改为仅关联凭证所需的 `user` 和 `order`，并增加源码合同防止回归。
