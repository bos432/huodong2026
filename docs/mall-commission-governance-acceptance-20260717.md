## 专项验收

```powershell
npm run acceptance:mall-commission-governance
```

- 脚本自登录并自动选择租户、商品、库存和会员地址。
- 自动创建直属代理及两级上级代理，创建专属推广码和渠道规则 `v1`。
- 订单支付后生成 L0、L1、L2 三条佣金，比例分别为 5%、2%、1%，均冻结规则版本、商品行、计佣基数和受益层级。
- 同业务键两路并发结算佣金 30，只生成一条结算调整流水。
- 全额退款后，未结佣金 28/29 归零并作废，已结佣金 30 生成待扣回。
- 同业务键两路并发确认扣回，只生成一条扣回完成流水。
- 最终存在结算、两条退款减佣、退款扣回和扣回完成共五条不可变调整流水。

## 整改记录

1. 修复单笔结算、批量结算、风险复核和扣回锁查询触发 TypeORM eager relation，导致 MySQL 超过 61 表 join 上限。
2. 上述资金写操作改为关闭 eager，只显式加载租户、店铺和订单关系。
3. 修复退款重算佣金时关闭 eager 后未显式加载租户、店铺和订单，导致调整流水写入缺少 `tenantId` 返回 500。
4. `mall-commission-governance` 从依赖手工令牌和九个业务 ID 的骨架升级为可重复执行、自建完整三层代理数据的专项脚本。
