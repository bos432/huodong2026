# PC 后台表格固定列移动适配验收（2026-07-20）

## 审计范围

- `apps/admin/src/views` 共发现 39 个页面、72 处 `fixed="left/right"` 或动态 fixed 表格列。
- 高风险操作列宽度包括订单 300px、管理员 500px、商城售后 470px、商家治理 700px 等。
- Element Plus 当前版本通过同一表格单元格的 `position: sticky` 实现固定列，窄屏时会覆盖其它字段。

## 真实缺陷

平台管理员在 390x844 打开活动订单页时，300px 固定操作列坐标为 `left=49/right=349`，覆盖几乎整个 390px 视口；页面没有水平溢出指标，但订单号、活动、用户和金额列被操作列遮挡。

修复前截图：`.local-logs/admin-table-responsive-20260720/orders-before-390x844.png`。

## 统一整改

- 在全局 `styles.css` 的 `max-width: 768px` 断点中，将 Element Plus 左右固定列的 `left/right` 设为 auto，移除固定列阴影。
- 不隐藏、不删除操作列；列仍保留在表格正常顺序中，可通过表格内部横向滚动访问。
- 同一断点统一收紧 page/table-card padding、允许 toolbar 换行，并将通用 form-grid 改为单列。
- 桌面断点不改变 sticky 行为。

## 浏览器结果

| 页面 | 固定列 | 390px 结果 |
|---|---:|---|
| 活动订单 | 300px 右操作列 | 从 `49-349` 移至 `1997-2297`，表格内部 `301/2260` 可滚动 |
| 管理员 | 500px 右操作列 | 移至 `1207-1707`，表格内部 `301/1670` 可滚动 |
| 商城售后 | 470px 右操作列 | 移至 `2081-2551`，不覆盖售后字段 |
| 志愿者 | 100px 左姓名列、190px 右操作列 | 姓名保持正常首列 `41-141`，操作移至 `1951-2141` |

- 四个代表页面均无页面级横向溢出。
- 1280x800 活动订单页操作列仍 sticky，`right=0`，坐标 `908-1208`。
- 浏览器控制台 warning/error 为 0。
- 修复后截图：`.local-logs/admin-table-responsive-20260720/orders-after-390x844.png`。

- API 全量 156 个测试文件、880 项通过。

## 剩余范围

该整改关闭所有已使用 Element Plus fixed 列的统一遮挡风险。特殊虚拟表格、第三方富文本、弹窗内超宽内容及真机横屏仍需在 `11.05` 后续抽查。
