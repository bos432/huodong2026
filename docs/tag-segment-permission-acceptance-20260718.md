## 2. 权限模型

| 权限 | 能力 |
|---|---|
| `tag.view` | 查看当前商家和岗位活动范围内的标签、分群、预览、快照和脱敏会员信息 |
| `tag.manage` | 新增/删除/批量维护标签，刷新行为标签，保存分群和创建快照；自动包含 `tag.view` |
| `tag.sensitive` | 查看标签、预览和快照成员完整手机号及快照创建人；自动包含 `tag.view`，不包含写权限 |

维护与敏感权限互不包含。会员运营账号可以维护标签和分群而不自动获得完整手机号；敏感审阅账号也不能新增、删除、刷新、保存或固化。

## 3. 本轮发现并修复的问题

### 3.1 单一 manage 权限

原标签、分群、预览和快照全部依赖 `tag.manage`，无法建立只读和敏感信息审阅账号。现拆为查看、维护、敏感三项权限，并同步 API、PC 权限目录、路由、菜单、默认运营角色和演示 seed。

### 3.2 完整用户实体泄露

原标签列表、分群预览和快照成员通过 eager relation 或 `leftJoinAndSelect` 返回完整用户实体，`sanitizeMemberDetail` 只移除 `passwordHash` 等少数字段，仍会返回：

- `openid`
- `unionid`
- `wechatAppId`
- 完整手机号
- 登录渠道和用户内部时间字段

现统一改为显式字段选择和白名单 DTO，只返回业务必要的会员 ID、昵称、手机号、来源渠道、等级和聚合指标。普通账号手机号服务端固定脱敏，PC 再使用 `maskPhone` 二次保护；敏感账号才可获得完整手机号。

### 3.3 岗位活动范围未覆盖会员标签和分群

原 `assertUserTenantAccess` 只检查商家归属，岗位限定账号仍可通过用户 ID 查看或维护同商家其他活动成员；分群预览、快照和行为标签刷新也默认覆盖全商家会员。

现新增会员活动范围约束：标签列表、单用户操作、批量会员标签、分群查询、快照成员和行为标签刷新均只处理管理员 `activity_ids` 范围内有报名关系的会员。范围外用户和对象返回 404。

### 3.4 平台标签可被租户猜 ID 删除

原删除标签使用通用租户断言，标签 `tenant=null` 时会被视为可访问，导致租户账号猜到平台标签 ID 后可以删除。现改为严格租户归属断言，平台标签和其他商家标签统一返回 404。

### 3.5 标签列表无分页和专属筛选项

原页面一次加载全部标签，活动筛选只能依赖外部 URL，分群规则中的会员等级也没有可选择的真实数据。现新增专属 options，返回岗位范围内最小活动对象和启用会员等级；标签列表支持 `page/pageSize`，每页最多 100 条，非法分页返回 400。

### 3.6 并发新增和审计不完整

原新增标签采用“先查后存”，并发请求可能触发唯一约束异常；单条新增和删除也没有完整操作审计。现保留数据库唯一约束并捕获重复键：并发相同标签只创建一次，另一请求返回 `idempotent=true`。新增、删除、批量活动标签、批量会员标签、分群创建/更新和快照均写入操作审计。

### 3.7 快照和输入边界不足

现补齐标签名、颜色、备注、分群名称、说明和分页边界校验；停用分群禁止创建快照。快照列表和成员使用最小投影，普通账号隐藏快照创建人，敏感账号可查看；跨范围分群和快照返回 404。

### 3.8 专属 options 查询排序列遗漏

首轮真实专项发现，活动 options 使用 `take(500)` 时 TypeORM 会生成分页子查询，但内部排序字段 `activity.createdAt` 未进入选择列，导致查询失败并被统一异常过滤器提示为缺少升级字段。现将排序列加入内部选择，返回 DTO 仍不暴露该字段，无需数据库 migration。

### 3.9 移动端布局溢出

首次 390×844 验收中，分群表单仍使用桌面 `12/8` 栅格和固定标签宽度，页面为 `351/384`、分群卡片为 `309/363`。现调整移动栅格、表单标签、输入宽度、筛选布局和表格容器，最终页面 `351/351`，两张卡片均 `309/309`。
