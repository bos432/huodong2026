# PC 后台弹窗与抽屉焦点验收报告

## 1. 验收范围

- 日期：2026-07-20
- 环境：`http://127.0.0.1:18080/admin`
- 视口：1280 x 800、390 x 844
- 场景：修改密码弹窗、订单退款弹窗、活动编辑抽屉及嵌套草稿恢复确认。
- 检查：打开焦点、模态语义、Esc 关闭、嵌套层级、关闭后焦点返回、控制台错误。

## 2. 基线结果

修改密码和订单退款由 Element Plus 单层焦点陷阱正确处理：

- 打开后焦点位于 `role=dialog / aria-modal=true` 容器内。
- Esc 可关闭弹窗。
- 修改密码关闭后返回“修改密码”按钮。
- 订单退款关闭后返回原订单行“申请退款”按钮。

活动编辑存在嵌套草稿确认时出现缺陷：关闭“恢复活动草稿”确认框后焦点落到 `BODY`，继续 Esc 关闭活动抽屉后仍无法返回原“编辑”按钮。

## 3. 整改

- 打开活动编辑前记录真实触发元素。
- 为活动编辑抽屉增加稳定类名和 `closed` 焦点恢复处理。
- 草稿确认消失后通过 `MutationObserver` 等待模态层实际退出，再把焦点移入活动抽屉关闭按钮。
- 活动抽屉关闭后优先返回仍连接在 DOM 中的原触发按钮；触发按钮失效时回退到后台主内容。
- 新增合同测试固定触发器记录、嵌套弹窗等待、抽屉关闭恢复和函数必须位于脚本块内。

首次补丁把 `runPrimaryAction` 落入样式块，专项字符串检查误通过，但 PC 类型检查失败。代码已移回 `</script>` 前，合同测试同步增加脚本位置断言，最终类型检查及构建通过。
