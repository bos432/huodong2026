# 运营巡检作用域与状态隔离验收报告

## 1. 验收范围

- 平台和商家进入运营巡检的权限。
- 巡检入口按当前账号真实权限过滤。
- localStorage 完成状态的账号、租户和本地日期隔离。
- 重置确认取消的无副作用行为。
- PC 桌面与 390×844 移动视口。

## 2. 路由与菜单

运营巡检不调用服务器写接口，路由允许以下任一权限：

- 平台：`system.view`
- 商家：`dashboard.view`

路由作用域为 `tenantOrPlatformAdmin`。平台入口位于“系统与安全”，商家入口位于“设置”。

## 3. 可达项规则

每个巡检项分别声明平台和商家所需权限。页面只显示当前账号可以实际进入的项目，不再展示点击后被路由回退的无权入口。

平台 `showcase_system_settings_read` 可见：

- 每日：上线体检、报名通道。
- 每周：无。
- 每月：备份恢复演练、通知服务余额。
- 合计：4 项。

商家 `showcase_admin` 可见：

- 每日：财务对账、报名通道。
- 每周：操作日志、管理员、代理结算、代理收款。
- 每月：通知服务余额、默认管理员复核。
- 合计：8 项。

## 4. 状态隔离

完成状态键格式：

```text
ops-routine:<tenantId或platform>:<admin_username>:<本地YYYY-MM-DD>
```

该格式解决：

- 同一浏览器不同管理员互相覆盖。
- 平台与商家状态串用。
- 不同租户状态串用。
- 上海时区凌晨使用 UTC 日期记到前一天。

localStorage 写入失败时，页面不会先更新内存状态，用户会看到“保存巡检状态失败”提示。

## 6. 浏览器验收

平台账号：

1. `showcase_system_settings_read / Qiwai123456` 可直接进入 `/admin/ops-routine`。
2. 菜单仅显示其已授权的系统设置、上线体检和运营巡检。
3. 巡检汇总为每日 `0/2`、每周 `0/0`、每月 `0/2`、总计 `0/4`。
4. 勾选上线体检后变为每日 `1/2`、总计 `1/4`。

商家账号：

1. 切换 `showcase_admin / Qiwai123456` 后巡检从 `0/8` 独立开始，未继承平台勾选状态。
2. 汇总为每日 `0/2`、每周 `0/4`、每月 `0/2`、总计 `0/8`。
3. 勾选财务对账后打开重置确认并取消，状态仍为每日 `1/2`、总计 `1/8`。
4. 页面不显示商家账号不可达的平台登录日志、验证码日志、上线体检和备份恢复。

视口与控制台：

- 桌面 `scrollWidth=clientWidth=1265`。
- 390×844 下页面 `scrollWidth=clientWidth=375`。
- 宽表仅在表格内部滚动，页面外壳无横向滚动。
- 最终刷新新增 console warning/error 为 0。

## 7. 保留数据

浏览器保留以下本地巡检状态，便于交付演示：

- 平台 `showcase_system_settings_read`：上线体检已完成，合计 `1/4`。
- 商家 `showcase_admin`：财务对账已完成，合计 `1/8`。

这些状态只存储在当前应用内浏览器的 localStorage，不写入数据库，也不会影响其他浏览器或设备。
