# 课程与多商户渠道对账最终验收报告（2026-07-20）

## 1. 验收范围

- 活动、课程和商城渠道账单的匹配、金额差异、未知订单、认领、解决、忽略和重新勾兑。
- 平台代收与商户直收账户隔离、相同渠道交易号防串账、重复导入幂等和绑定防漂移。
- 账单与统一/商城支付流水的双账本状态同步、整数分口径和统一资金一致性。
- 商家、店铺员工和跨租户权限边界，供应商原始报文及订单隐私字段保护。
- PC 桌面与 390x844 页面展示、操作区响应式和表格可用性。

## 2. 完成实现

- 统一渠道账单支持活动订单和课程订单，课程匹配后写入 `businessType=course` 的统一支付流水；课程账单列表、差异处理和财务 Excel 均显示业务类型与课程名称。
- 商城账单以 `provider + accountScope + transactionNo` 唯一；平台代收使用 `tenant:{tenantId}:platform`，商户直收使用 `merchant:{merchantId}`。
- 同一账户范围内的既有账单禁止跨商家、跨店铺或跨订单改绑；不同收款账户可以安全复用同一渠道交易号。
- 商城导入结果区分 `importedCount/updatedCount/processedCount`，更新时同步刷新 `amountFen`。
- 商城账单解决、忽略和重新勾兑会同步对应支付流水的对账状态、差异类型与处理说明。
- 商城账单列表、导入、拉取、认领和处理响应统一清理 `rawPayload`、租户设置、订单业务快照和地址快照。
- 财务页窄屏工具栏改为两列；商城渠道账单取消窄屏固定操作列，使用表格内部横向滚动，不再覆盖流水内容。

## 5. 失败路径与整改

1. `.local-logs/mall-statement-1784528444492/result.json`：验收脚本错误假设 `users.tenantId` 存在，在写业务数据前失败；改为从租户商城订单获取会员。
2. `.local-logs/mall-statement-1784528476668/result.json`：前六组业务断言通过，最后发现账单列表仍返回 `rawPayload`、租户设置和地址快照；列表与拉取接口随后统一脱敏，最终专项通过。
3. PC 财务页首次浏览器加载旧静态构建，课程名称未显示；重新构建 PC 后业务标签和课程名称正确。
