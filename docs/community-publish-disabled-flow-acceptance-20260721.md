# 活动心得未开放流程整改验收（2026-07-21）

## 问题与根因

- `qiwai-showcase` 当前配置为 `community=false`、`communityPublish=false`。
- 报名详情仍显示普通“分享活动心得”按钮；点击后进入发布页，页面用 300ms Toast 提示后立即 `reLaunch` 首页。
- 页面切换吞掉 Toast，用户只看到跳首页，不知道功能为何不可用。

## 整改

- 报名详情同步读取功能开关，未开放时直接隐藏“分享活动心得”入口；后台同时开启 `community` 和 `communityPublish` 后自动显示。
- 后台将 `communityPublish -> community` 建模为明确依赖：开启“发布心得/打卡”时自动开启“共修动态/心得”，关闭父功能时同步关闭子功能，并在开关卡片内常驻显示依赖说明。
- 同类的 `forumPost -> forum` 也使用相同联动，避免只靠教程或运营人员记忆维护合法组合。
- 点击已显示入口前仍会刷新并复核后台开关，防止操作期间配置变化。
- 直接访问受限页面时也显示同一弹窗；确认后优先返回上一页，只有无上一页时才带租户参数回首页。
- 增加弹窗互斥，避免 App 和页面守卫并发触发重复弹窗。

- 直接打开受限发布页仍显示完整弹窗；点击“我知道了”后按页面栈返回或安全回首页。

- 系统设置桌面和 390x844 均无横向溢出，依赖文字与开关无重叠。
- 控制台 warning/error 0；安全扫描和监控通过。

## 结论

受功能开关限制时不再静默跳首页；后台也不会产生“子功能开启但父功能关闭”的无效组合，教程仅作为补充说明。
