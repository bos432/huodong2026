资料来源：git 提交历史、线上部署记录、用户反馈截图/终端输出、维护笔记。本文按“可复盘、可检索、可继续维护”的方式整理；功能建设型提交只在它解决了具体风险、缺口或线上问题时列入。

## 遗留和每次修复后必查

- 小程序端发布后如果改了 `apps/mobile`，必须重新上传微信体验版并提交审核。
- 只改 API/PC 后台/文档通常不需要小程序审核，但要部署 API/admin。
- 线上部署后必须核对 `api/health/ready` 的 `release.commit`。
- GitHub 推送失败时先看是否走了全局代理；不要反复盲推。
- 现场签到/扫码、手机端管理端发布、未登录导航、活动列表租户过滤，是上线阶段最容易回归的四类问题。
- 全流程交付前至少测：平台超管、商家管理员、手机管理员/签到员、普通用户报名。
