## 2. 数据模型与迁移

- 新增 `member_point_rules`，平台保存规则模板，租户保存独立规则实例。
- 积分规则按业务事件唯一，支持固定积分、金额比例、成长值策略、有效天数和版本号。
- `member_point_logs` 增加请求积分、变动前后余额、关联原流水、批次键、规则快照和业务元数据。
- `member_profiles` 增加积分欠额，退款扣回不足不会产生负余额，而是形成后续可自动偿还的欠额。
- 积分唯一键升级为 `tenantScopeKey + userId + sourceType + sourceId`，同一业务事件可在不同租户独立处理。
- 新增关联原流水外键和到期批次索引，退款、抵扣返还、欠额偿还可追溯到原始积分流水。
- migration `1783880000000-MemberPointLedgerGovernance` 修复历史活动/商城退款扣回、评价租户归属、负余额和余额快照。

## 3. 租户规则与事件幂等

- 慢π演示中心拥有 4 条独立积分规则，活动支付规则当前版本为 v5，恢复为每 `¥1.00` 发 1 分。
- 租户规则更新只生成本租户新版本，不修改平台模板或其他租户实例。
- 历史积分流水保存完整规则快照，后续修改规则不会重算旧流水。
- 管理员积分调整必须提供稳定业务幂等键；同会员同租户操作使用进程内排队、MySQL 命名锁和事务。
- 十路并发提交同一积分调整只生成一条账本流水，其余请求返回幂等结果。
- 普通积分扣减禁止超过可用余额，退款扣回允许形成欠额但不会形成负余额。
- 活动评价按活动所属租户选择规则，不再根据调用入口误落到平台账本。

## 4. 退款冲正与欠额偿还

- 活动和商城退款均按“原奖励积分 × 累计退款金额 / 原支付金额”计算累计目标扣回。
- 拆分退款只扣除本次新增差额，不会因多次退款重复扣回。
- 兼容商城历史积分流水中订单 ID、退款 ID 和退款号三种 `sourceId` 语义。
- 两笔拆分退款对原 5 分奖励分别请求扣回 1 分和 4 分，累计精确为 5 分。
- 退款时余额已用完，两条退款流水实际变动均为 0，请求积分仍保留为 `-1/-4`，并形成 5 分欠额。
- 后续奖励 8 分先生成奖励流水，再自动生成 `points_debt_recovery -5`，最终可用积分 3、欠额 0。
- 退款流水和欠额偿还流水均返回 `relatedLogId`，PC 后台可查看来源编号和关联流水编号。

## 5. 批次过期

- 奖励积分可按规则或管理员调整设置到期时间，长期积分保持无到期日。
- 消费按最早到期批次优先，避免长期积分先于临期积分被消耗。
- 生命周期扫描只处理已到期且未处理批次，并记录 `expiryProcessedAt`。
- 到期校准生成 `points_expiry_reconciliation` 流水，记录到期积分、校准积分和批次键。
- 同一到期批次重复扫描只生成一条校准流水，不重复扣减或增加积分。
