# 商城收款配置与支付日志状态验收报告

## 1. 验收范围

- PC 后台商城收款配置：店铺范围、支付就绪度、收款账户读取与保存目标。
- PC 后台商城支付日志：支付流水、支付回调、退款日志、佣金、渠道账单。
- 请求竞态、旧数据清理、分区失败、独立恢复、资金操作目标复核和移动端布局。
- 本批只打开渠道账单拉取确认弹窗并取消，未提交账单、佣金或收款账户写操作。

## 2. 实现结果

### 2.1 商城收款配置

- 店铺列表、支付就绪度和收款账户分别使用请求代次，迟到响应不能覆盖新店铺。
- 店铺读取开始即清除旧店铺和旧收款数据；失败后不保留上一店铺的资料。
- 支付就绪度与收款账户使用 `Promise.allSettled` 独立恢复。
- 配置检测、账户保存和凭据上传期间锁定店铺范围；账户保存复核店铺、账户 ID 和渠道。
- 店铺 `#38` 正常显示，商城开放、平台代收；本地未配置正式微信证书，因此就绪度如实显示“配置未就绪”。

### 2.2 商城支付日志

- 页面拆为支付流水、支付回调、退款日志、佣金组和渠道账单五个读取分区。
- 五个分区分别维护 loading、error 和 sequence；刷新开始清空对应旧数据。
- 佣金明细、摘要、推广人汇总和调整流水使用 `Promise.allSettled`，错误会列出具体失败来源。
- 佣金结算、批量结算、风险复核和扣回在提交前复核佣金 ID、订单号、店铺、筛选范围和列表代次。
- 账单拉取、导入、认领、重勾兑、解决和忽略在提交前复核店铺、交易号、筛选范围和列表代次。
- 资金写操作或导出期间锁定租户、店铺、日期和状态筛选。
