# 慢π城市活动与公益共修平台系统说明与开发方案

## 一、项目概述

慢π是一套面向城市活动、文化共修、公益志愿、课程交付和本地生活商业运营的数字化平台。系统以「城市/商家」为运营单元，通过 H5、小程序、后台管理端、手机管理端四个入口，把活动报名、订单收款、签到核销、内容社区、课程学习、公益透明公示、志愿服务、证书核验、商城交易和多角色运营管理整合到一套系统中。

简单说，它不是单一的活动报名工具，而是一个可复制到多个城市、多个商家、多个运营团队的本地文化生活运营底座。

平台当前已经完成可演示、可部署、可运营的 v1 版本，具备真实活动组织、用户报名、交易确认、内容沉淀、论坛互动、志愿服务、证书核验和后台分角色管理能力。

## 二、项目要解决的问题

### 1. 线下活动组织分散
很多城市文化活动、公益活动、课程、共修活动依赖微信群、表格、人工收款和人工签到。问题是：
- 报名信息散落，难以统计。
- 收款和退款需要人工核对。
- 活动后用户关系沉淀弱。
- 用户参加一次活动后很难持续运营。

### 2. 城市运营难复制
如果要在多个城市开展慢π活动，需要统一标准，又要允许每个城市独立运营。常见问题是：
- 每个城市都要重复搭系统。
- 总部看不到城市数据。
- 权限边界不清晰。
- 新城市启动早期缺少默认入口和内容承接。

### 3. 公益、志愿和文化内容缺少可信闭环
公益、志愿者、文化大使、课程和共修内容都有长期运营价值，但传统方式很难形成完整链路：
- 公益资金和项目进展不透明。
- 志愿服务时长无法系统累计。
- 证书缺少统一发放和核验。
- 共修心得和活动反馈无法沉淀为社区资产。
- 大使招募缺少线索跟进和激活机制。

### 4. 商业化和公益化割裂
慢π需要同时承载活动、课程、公益、志愿、商城和城市合伙人体系。如果系统割裂，会导致：
- 用户在不同工具间跳转。
- 数据无法统一分析。
- 平台收入模型不清晰。
- 投入的内容和运营无法形成复利。

## 三、产品定位

慢π平台定位为：

**城市文化活动与公益共修运营 SaaS 平台。**

它面向三类客户和参与方：
- 平台总部：统一管理城市、品牌、规则、数据、系统配置和商业化策略。
- 城市/商家运营方：发布活动、管理报名、运营课程、维护社群、处理订单和用户。
- 普通用户：报名活动、购买课程、参与共修、发帖交流、申请志愿服务、获取证书。

它的核心价值是：
- 把线下活动线上化。
- 把一次性参与转为长期用户关系。
- 把活动内容转为社区内容资产。
- 把公益和志愿服务转为可信记录。
- 把单城运营转为多城复制模型。

## 四、系统整体架构

### 1. 前台用户端
支持 H5 和微信小程序。

主要能力：
- 城市/商家入口识别。
- 活动列表和详情。
- 未登录跳转登录后回到报名位置。
- 报名、订单、付款状态、签到码。
- 活动心得发布和图片上传。
- 共修动态、打卡、论坛。
- 课程浏览、下单、学习。
- 商城浏览、购物车、订单、物流。
- 我的报名、我的订单、我的课程、我的证书、我的帖子。

### 2. 后台管理端
面向平台超管、商家管理员、运营、财务、签到、店铺负责人、店铺财务、代理负责人等角色。

主要能力：
- 商家和城市管理。
- 活动、报名、订单、签到。
- 课程、共修、论坛。
- 公益池、志愿者、证书、文化大使。
- 商城、优惠券、拼团、库存、售后、结算。
- 营销弹窗、广告位、首页装修。
- 财务、导出、日志、系统设置。

### 3. 手机管理端
面向现场运营人员和轻后台用户。

主要能力：
- 手机端登录管理。
- 活动发布和编辑。
- 活动列表。
- 报名查看。
- 订单查看。
- 签到核销。

### 4. 服务端和数据库
当前技术栈：
- 前台：uni-app，支持 H5 和微信小程序。
- 后台：Vue 3 + Element Plus。
- API：NestJS。
- 数据库：MySQL。
- ORM 和迁移：TypeORM migrations。
- 部署：Nginx + PM2 + 宝塔服务器。
- 构建与验收：自动化 smoke、浏览器验收、发布前审计。

## 五、核心功能详细说明

### 1. 多城市/多商家入口
系统以商家或城市为内容分发单元。用户打开小程序或 H5 时，会自动确定进入哪个城市。

入口优先级：
1. 分享链接中的城市/商家编码。
2. 用户手动选择的城市。
3. 定位匹配城市。
4. 后台配置的默认城市。
5. 构建默认城市。
6. 第一个可用商家。

投资价值：
- 适合总部统一品牌、多城市复制。
- 新城市早期即使没有定位量，也能进入默认城市承接内容。
- 分享传播可以精准带入某个城市或活动。

### 2. 活动报名系统
活动是平台最基础的交易和用户增长入口。

功能包括：
- 活动分类。
- 活动详情。
- 免费活动和付费活动。
- 报名字段配置。
- 名额管理。
- 订单生成。
- 线下收款确认。
- 余额支付。
- 报名详情。
- 签到码生成。
- 后台核销。
- 退款申请和财务处理。

已支持闭环：
用户看活动 -> 登录 -> 报名 -> 生成订单 -> 支付或确认收款 -> 生成签到码 -> 到场核销 -> 形成参与记录。

### 3. 未登录报名跳转
用户未登录时可以浏览活动。点击报名后自动跳转登录，登录完成后回到原活动报名位置。

这对转化率很重要：
- 不强迫用户一进来就登录。
- 用户产生报名意愿后再登录。
- 登录后不丢失原路径，减少流失。

### 4. 活动心得和图片发布
用户参加活动后，可以发布心得、感悟和照片。后台审核通过后展示。

价值：
- 把一次活动沉淀成内容资产。
- 提升新用户信任感。
- 为后续活动、课程和论坛提供内容素材。

### 5. 完整论坛 v1
论坛是本轮新增的重要社区能力，把原本简单评论升级为可运营的社区模块。

前台功能：
- 论坛首页。
- 版块列表。
- 帖子详情。
- 发帖。
- 一级回复。
- 楼中楼回复，最多两层。
- 收藏。
- 举报。
- 我的帖子。
- 我的回复。
- 我的收藏。

后台功能：
- 版块管理。
- 帖子审核。
- 回复审核。
- 举报处理。
- 置顶。
- 精华。
- 审核模式配置。

内容安全：
- 默认审核制。
- 前台只展示审核通过内容。
- 小程序审核版可隐藏发帖入口。

投资价值：
- 用户不再只是报名者，而是社区成员。
- 活动后的讨论、心得、问答可以长期沉淀。
- 精华和置顶机制有利于形成内容秩序。

### 6. 共修动态和打卡
共修动态用于承接修习、阅读、课程、活动心得等轻内容。

功能包括：
- 共修活动。
- 打卡任务。
- 动态发布。
- 评论审核。
- 点赞、评论、分享统计。
- 今日互动统计。
- 待审核动态和评论提醒。

价值：
- 适合文化、身心成长、学习型社群。
- 可把用户的短期活动参与变成长期打卡和陪伴。

### 7. 课程管理
课程模块支持从线下活动延展到线上课程交付。

后台能力：
- 课程发布和草稿。
- 课程封面。
- 讲师头像。
- 分类。
- 标签。
- 排序。
- 评分和热度展示。
- 章节课时。
- 免费试看。
- 课程订单。
- 待确认收款。

前台能力：
- 课程列表。
- 课程详情。
- 下单。
- 学习权限。
- 播放/学习进度。
- 我的课程。

商业价值：
- 活动可沉淀为课程产品。
- 讲师、课程、社群可以组成复购体系。
- 适合知识付费、文化教育和会员权益。

### 8. 公益池
公益池用于管理公益资金、项目、拨付和透明公示。

功能包括：
- 可用余额。
- 累计计提。
- 累计拨付。
- 公开项目数。
- 待执行项目。
- 待验收项目。
- 项目说明。
- 拨付记录。
- 拨付凭证。
- 执行动态。
- 公开状态。
- 异常提醒。

透明度提醒包括：
- 有拨付无凭证。
- 有项目无动态。
- 已执行未验收。

价值：
- 提升公益可信度。
- 适合对外公示和品牌责任建设。
- 可与志愿者、证书、城市活动联动。

### 9. 文化大使招募
文化大使模块本质上是一个轻 CRM 系统，用于招募、跟进和激活核心用户。

功能包括：
- 线索列表。
- 来源记录。
- 优先级。
- 五项评分。
- 下一次跟进时间。
- 最近跟进结果。
- 待跟进、高意向、待面谈、已激活、超期未跟进看板。
- 快捷跟进抽屉。

价值：
- 把热心用户转化为大使、志愿者或城市共建者。
- 降低城市扩张时的招募和管理成本。
- 为后续城市合伙人、志愿队伍和社群运营打基础。

### 10. 志愿者档案与证书
志愿者模块支持任务、报名、审核、服务记录、时长累计和证书发放。

完整闭环：
任务发布 -> 用户报名 -> 后台审核 -> 登记服务记录 -> 累计服务时长 -> 自动更新等级 -> 发放证书 -> 用户查看证书 -> 编号公开核验。

证书包含：
- 证书名称。
- 证书编号。
- 志愿者姓名。
- 服务时长。
- 等级。
- 发证时间。
- 发证人。
- 关联服务记录。
- 撤销状态。

后台支持：
- 发证。
- 补发。
- 查看。
- 下载/打印。
- 撤销。
- 撤销日志。

v1 固定模板：
- 慢π公益志愿服务证书。
- 公益大使证书。
- 城市共建者证书。

价值：
- 志愿服务从口头记录变成可信数据。
- 证书可核验，适合公益、校园、机构合作和城市品牌共建。

## 六、商业模式设计

### 1. 活动交易收入
平台可从付费活动、课程活动、工作坊活动中获取：
- 平台服务费。
- 报名手续费。
- 城市运营分成。
- 讲师合作分成。

### 2. 课程收入
课程模块支持一次活动转化为长期课程产品。

收入来源：
- 单课售卖。
- 系列课售卖。
- 会员权益课程。
- 讲师合作分账。

### 3. 城市加盟和 SaaS 服务费
平台具备多城市、多商家复制能力，可向城市运营方收取：
- 系统开通费。
- 年服务费。
- 运营工具费。
- 数据和会员管理服务费。

### 4. 商城交易与本地商家合作
商城可承载：
- 慢π自营商品。
- 城市文化产品。
- 课程周边。
- 公益联名产品。
- 本地商户合作商品。

收入来源：
- 商品毛利。
- 商户佣金。
- 结算服务费。
- 活动套餐销售。

### 5. 广告和品牌合作
首页、活动页、弹窗、广告位、城市专题页都可以成为商业合作资源。

收入来源：
- 品牌广告。
- 城市活动冠名。
- 课程或公益项目赞助。
- 本地商户推广。

### 6. 证书和志愿服务体系
证书本身不建议简单售卖，但可以作为机构合作、公益项目、会员权益和城市共建项目的一部分，形成：
- 机构服务费。
- 公益项目运营费。
- 志愿者管理服务费。
- 证书核验和档案服务能力。

## 八、技术方案

### 1. 前端技术
H5 和小程序使用 uni-app，一套代码支持多端发布。

优势：
- 同时覆盖微信小程序和 H5。
- 降低开发成本。
- 小程序适合微信生态传播，H5 适合分享和快速访问。

后台使用 Vue 3 和 Element Plus。

优势：
- 管理端开发效率高。
- 适合复杂表格、筛选、抽屉、表单和权限控制。

### 2. 后端技术
后端使用 NestJS。

优势：
- 模块化清晰。
- 适合长期维护。
- 权限、控制器、服务层、DTO 边界清楚。
- 方便扩展新的业务模块。

### 3. 数据库方案
数据库使用 MySQL，配合 TypeORM migrations。

优势：
- 适合订单、报名、用户、财务、日志等结构化数据。
- 迁移机制适合生产环境稳定升级。
- 便于后续做 BI 和经营分析。

### 4. 部署方案
当前采用：
- 宝塔服务器。
- Nginx 反向代理。
- PM2 管理 API 进程。
- 静态文件发布 H5 和后台。
- API 健康检查。

生产部署流程：
拉代码 -> 安装依赖 -> 构建 -> 数据库迁移 -> 发布静态文件 -> 重启 API -> 健康检查。

项目内置多层验收：
- API 单元测试。
- smoke 业务验收。
- 浏览器自动化验收。
- 小程序构建检查。

- 生产配置检查。

这说明系统不仅有功能页面，也具备持续交付和质量控制能力。

## 十二、风险与应对

### 1. 内容安全风险
应对：
- 默认审核制。
- 举报处理。
- 小程序审核版隐藏敏感入口。
- 后续可接入内容安全 API。

### 2. 支付和资金合规风险
应对：
- 真实支付上线前保留线下确认和余额支付。
- 上线微信支付前单独做商户资质、回调验签、退款和对账验收。
- 公益资金展示强调透明记录，不做夸大承诺。

### 3. 多城市运营质量不一致
应对：
- 平台统一权限和模板。
- 城市运营看板。
- 默认城市配置。
- 标准操作手册。

### 4. 初期内容不足
应对：
- 默认城市承接。
- 运营精选帖子。
- 活动心得沉淀。
- 大使招募和志愿者体系带动种子内容。
