# 部署文档

## 1. 环境要求

| 组件 | 建议版本 |
| --- | --- |
| Linux | Ubuntu 22.04+/Rocky Linux 9+ |
| Node.js | 22 LTS 或 24 LTS |
| npm | 与 Node 配套版本 |
| MySQL | 8.0/8.4 |
| Nginx | 1.24+ |
| PM2 | 最新稳定版 |
| Docker 可选 | Docker 24+、Compose v2 |

不要使用 Node 25 构建 uni-app 小程序。项目根命令 `npm run build:mobile:mp-weixin` 已能自动选择工作区内兼容的 Node 22/24。

## 2. 关键部署原则

- 已有数据库：始终设置 `DB_SYNCHRONIZE=false`，执行 migration。
- 首次全新空库：也建议 `DB_SYNCHRONIZE=false`，通过项目 migration/初始化流程创建结构。
- 只有临时开发库可以短暂使用 synchronize；生产和持久化 Docker 卷禁止开启。
- 正式环境禁止默认密码和开发验证码模式。
- 真实支付证书和短信参数未配置完成前，相关生产开关保持关闭。

## 3. 安装依赖与质量检查

```bash
cd /path/to/project
npm run ci:install
npm run ci:verify
```

如果是日常更新，也可以按包安装：

```bash
npm install --prefix packages/shared
npm install --prefix apps/api
npm install --prefix apps/admin
npm install --prefix apps/mobile --legacy-peer-deps
```

## 4. 本地 Docker 部署

1. 复制配置：

```powershell
Copy-Item deploy/.env.local-docker.example deploy/.env.local-docker
```

2. 修改数据库密码、JWT、H5 密钥等默认值。

3. 构建前端并启动：

```powershell
npm run build
docker compose -p activity-registration --env-file deploy/.env.local-docker up -d --build
docker compose -p activity-registration ps
```

4. 健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:18080/api/health/ready
```

5. 停止服务但保留数据：

```powershell
docker compose -p activity-registration stop
```

不要执行 `down -v`，否则会删除数据库卷和保留测试数据。

## 5. 宝塔 + PM2 + Nginx 部署

目标目录示例：`/www/wwwroot/rd.chaimen666.com`。

```bash
cd /www/wwwroot/rd.chaimen666.com
set -e
export PATH=/www/server/nodejs/v22.22.3/bin:$PATH

git fetch origin feature/qiwai-ui-experiment
git pull --ff-only origin feature/qiwai-ui-experiment

npm run ci:install
npm run ci:verify
```

准备生产配置：

```bash
cp deploy/.env.production.example deploy/.env.production
chmod 600 deploy/.env.production
```

必须替换所有 `change-me`，至少配置：

- `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`DB_PASSWORD`
- `JWT_SECRET`、`H5_AUTH_SECRET`
- `CORS_ORIGIN`、`PUBLIC_H5_ORIGIN`、`PUBLIC_ADMIN_ORIGIN`、`PUBLIC_API_ORIGIN`
- 短信、微信登录和支付所需参数
- `DB_SYNCHRONIZE=false`

构建并写入版本：

```bash
COMMIT=$(git rev-parse --short HEAD)
BUILD_TIME=$(date -Iseconds)
export BUILD_COMMIT="$COMMIT"
export BUILD_TIME="$BUILD_TIME"

npm run build
npm run build:mobile:mp-weixin
```

数据库变更前先备份：

```bash
npm run db:backup
```

按仓库现有 migration 流程执行迁移，确认成功后启动或重启 API：

```bash
pm2 restart activity-api --update-env || pm2 start apps/api/dist/main.js --name activity-api
pm2 save
```

Nginx 建议映射：

```nginx
root /www/wwwroot/rd.chaimen666.com/apps/mobile/dist/build/h5;

location ^~ /admin/ {
    alias /www/wwwroot/rd.chaimen666.com/apps/admin/dist/;
    try_files $uri $uri/ /admin/index.html;
}

location ^~ /api/ {
    proxy_pass http://127.0.0.1:3000/api/;
}

location ^~ /uploads/ {
    proxy_pass http://127.0.0.1:3000/uploads/;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

```bash
nginx -t
/etc/init.d/nginx reload
```

## 6. 部署后验收

```bash
curl -s https://your-domain.example/api/health/ready
curl -s https://your-domain.example/admin/version.json
curl -s https://your-domain.example/version.json
pm2 status
```

期望结果：

- API `ready=true`。
- API、Admin、H5 的 commit 一致。
- PM2 中 `activity-api` 为 online。
- H5 首页、后台登录页和上传文件可访问。

建议继续执行：

```bash
API_BASE=https://your-domain.example/api WEB_BASE=https://your-domain.example npm run smoke:online-showcase
```

## 7. 微信小程序发布

构建目录：`apps/mobile/dist/build/mp-weixin`。

1. 微信开发者工具导入该目录。
2. 配置合法域名和 AppID。
3. 验证微信登录、手机号绑定、首页、活动报名、支付、签到码和移动管理端。
4. 上传体验版并进行真机测试。
5. 测试通过后提交审核和发布。

## 8. 备份与恢复

备份：

```bash
npm run db:backup
npm run db:prune-backups
```

恢复前停止写入流量，确认备份文件后执行：

```bash
npm run db:restore -- /absolute/path/to/backup.sql.gz
```

恢复后必须检查 health、登录、订单、报名和财务数据。

## 9. 回滚

```bash
cd /www/wwwroot/rd.chaimen666.com
git log --oneline -10
git checkout <previous-stable-commit>
npm run ci:install
npm run build
pm2 restart activity-api --update-env
nginx -t && /etc/init.d/nginx reload
```

如果本次部署包含数据库 migration，应按照对应 migration 的回滚方案处理，不能只回滚代码。回滚前保留当前数据库备份和发布日志。
